# Early chunk isolation

Buffered pre-manifest chunks retain their transfer ID, index and ciphertext. The authenticated manifest selects only chunks belonging to that transfer. Early data never extends the pending handshake’s idle timeout; accepted validated spool writes and decrypted output refresh receive progress instead. Malformed IDs and oversized early chunks are dropped before buffering, and late terminal-state chunks cannot restart an idle timer.

Two focused negative controls fail on the unchanged private-storage production engine: a stray chunk prevents an otherwise valid early transfer from becoming Ready, and repeated unrelated chunks keep an unfinished handshake alive. The repaired engine passes all 22 cases without skips, including saving the valid early transfer byte-for-byte after discarding the unrelated chunk. The full client/server build and all 40 enabled local suites pass in 56.94 seconds (41 registered, OverlayTest disabled).

This is client-side isolation. The existing server still broadcasts file chunks to capable channel peers, so recipient-only relay, actual multi-recipient concurrent server delivery, files beyond the meter window, acknowledgements and slow-receiver backpressure remain open. Native Linux/Windows and hosted checks of this new source are pending. The first timer fixture omitted a required signing callback; that fixture exception was corrected before the retained negative control and is excluded from acceptance.

Both new routing/timeout controls pass, with all 16 [producer checksums](../../hosting/results/2026-10-10/windows-early-routing/SHA256SUMS) verified against committed bytes. This supplements the Mac regression; server recipient filtering and installed GUI remain open.
