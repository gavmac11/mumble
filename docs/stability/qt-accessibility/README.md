# macOS Qt accessibility release blocker

On macOS 26.6.2 ARM64, adding a favorite server and inspecting its selected tree through Codex Computer Use crashed both the local Qt 6.11.1 developer client and the packaged Qt 6.10.0 preview from source `0e0671cf5d58cffe905c83e162dd287686a666f2`. The main-thread report is `EXC_BAD_ACCESS / SIGSEGV` at `QMacAccessibilityElement::accessibilitySelectedChildren`. The [sanitized Mac record](../mac-native-preparation-20261010.json) includes the preview archive/binary identities and initial repeated crash traces.

A [standalone Qt fixture](../../../scripts/hosting/native_qt_tree_repro) reproduces the crash without Mumble code. Build it with a matching Qt Widgets SDK and use the native UI controller to inspect the empty tree, click **Add and select private test row**, and inspect again. It deliberately creates a hidden expanded parent, unhides it on insertion, and selects the child. It contains no network, media, credentials, personal files or external UI automation. It is not registered as a headless CTest test.

## Diagnosis and private validation

Qt's [Cocoa ownership change](https://github.com/qt/qtbase/commit/b1ed5f656f064e553b33752f8e87d2f5b9553e38) deletes Qt interfaces while releasing native row/column representations. The [Qt source](https://github.com/qt/qtbase/blob/5a8637e4516bc48a0b3f4b5ec3b18618b92e7222/src/plugins/platforms/cocoa/qcocoaaccessibilityelement.mm) documents that synthesized elements borrow the parent table's ID. Qt Widgets also retains real cell interface IDs in its table model cache. Native representation lifetime therefore cannot determine C++ interface lifetime.

The first patch guarded parent-managed IDs. Its insertion/connection checks passed, but a later real LAN disappearance crashed at `QAccessibleTable::modelChange` through `ConnectDialog::onUpdateLanList`. That repair is insufficient. The expanded Qt-only fixture's removal sequences did **not** reproduce that second crash; only the real client's Bonjour row removal did.

The revised [patch](qt-parent-owned-accessibility.patch) removes Cocoa's interface deletion on native element cleanup. Qt retains responsibility for deleting its C++ interfaces when the widget/model changes. Native row/column arrays are still released. The patch applies without fuzz to exact upstream Qt 6.10.0 and 6.11.1. The private revised Qt 6.11.1 plugin survives the original insertion/selection inspection and the actual client LAN disappearance trigger. This is limited reproduction evidence, not proof that every accessibility lifetime or stale-row problem is resolved.

A separate native quit crash occurred **after** the normal-quit marker was saved: Qt plugin unload called Mumble's message handler after spdlog's registry teardown. The earlier marker/process observations did not establish clean termination. The client now restores the previous Qt handler on normal return, before application/static-plugin destruction. A private late-message control without restoration terminates with SIGSEGV; `TestQtLogger` checks normal child-process exits after logger shutdown, repeated initialization and preservation of a later handler owner.

Two disposable developer clients using the revised plugin connect to the owned loopback server, unlock existing CLI-created fixture identities and show identical safety numbers. An initial verification delay times out; retry reaches recipient **Click to save**. Saving and a downloaded-file hash remain unverified because native coordinate control returns `windowNotFoundAtPosition`. The safety QR appears solid black; numeric verification succeeds. Both clients then quit, log Cocoa unload and leave no live process or new Mumble crash report. The [38 enabled local CTest suites](local-regression.txt) pass in 42.25 seconds, with zero execution failures/skips; OverlayTest remains disabled (39 registered). These are developer-runtime checks, not shipping installation, complete delivery or media acceptance.

## Shipping build repair

For macOS static Qt **6.10.0** builds, the client now rebuilds Cocoa from pinned upstream source with the patch. The source archive SHA-256, original accessibility file SHA-256 and corrected file SHA-256 are checked. Reconfiguration accepts only the verified original or corrected file. Qt's import/interface metadata is retained, while its imported Cocoa archive points to the new archive in this build. The installed/cached vcpkg archive is never changed. The downloaded Qt source retains its upstream license; existing Qt license distribution continues.

The vendor target follows Qt's own compiler/deployment requirements, compiles without Mumble's application warning flags, and disables unity compilation. Cocoa targets macOS 14 as upstream requires; the product minimum stays macOS 15. Windows/Linux and other Qt versions do not enter this repair path. An explicit `qt-cocoa-accessibility-repair=OFF` option exists for the unpatched comparison build; that build remains unqualified for release while this crash is open.

The vendor target also compiles and links as a static Cocoa archive against matching private Qt 6.11.1 source/SDK. A standalone fixture importing it with `Q_IMPORT_PLUGIN`, with dynamic platform lookup disabled in its private configuration, survives two native insert/select/AX reads. The first read exposes an incomplete row tree; a later full read exposes the fixture, so complete accessibility semantics remain unqualified. This uses shared Core/Gui/Widgets and does not validate the shipping all-static Qt 6.10.0 SDK.
