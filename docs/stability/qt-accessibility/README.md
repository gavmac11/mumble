# macOS Qt accessibility release blocker

On macOS 26.6.2 ARM64, adding a favorite server and inspecting its selected tree through Codex Computer Use crashed both the local Qt 6.11.1 developer client and the packaged Qt 6.10.0 preview from source `0e0671cf5d58cffe905c83e162dd287686a666f2`. The main-thread report is `EXC_BAD_ACCESS / SIGSEGV` at `QMacAccessibilityElement::accessibilitySelectedChildren`. The [sanitized Mac record](../mac-native-preparation-20261010.json) includes the preview archive/binary identities and initial repeated crash traces.

A [standalone Qt fixture](../../../scripts/hosting/native_qt_tree_repro) reproduces the crash without Mumble code. Build it with a matching Qt Widgets SDK and use the native UI controller to inspect the empty tree, click **Add and select private test row**, and inspect again. It deliberately creates a hidden expanded parent, unhides it on insertion, and selects the child. It contains no network, media, credentials, personal files or external UI automation. It is not registered as a headless CTest test.

## Diagnosis and private validation

Qt's [Cocoa ownership change](https://github.com/qt/qtbase/commit/b1ed5f656f064e553b33752f8e87d2f5b9553e38) adds cache/interface deletion while releasing row/column representations. The [Qt source](https://github.com/qt/qtbase/blob/5a8637e4516bc48a0b3f4b5ec3b18618b92e7222/src/plugins/platforms/cocoa/qcocoaaccessibilityelement.mm) documents that synthesized rows/columns/cells borrow the parent table's accessibility ID. The working diagnosis is that deleting those borrowed IDs invalidates the table/interface during selected-child enumeration. This is supported by the controlled reproduction and two guarded deletion sites; it is not a claim that all Qt accessibility ownership bugs are resolved.

The [patch](qt-parent-owned-accessibility.patch) skips interface deletion for parent-managed synthesized elements and preserves deletion for real cached interfaces. It applies without fuzz to exact upstream Qt 6.10.0 and 6.11.1. A private Qt 6.11.1 Cocoa plugin built with the patch survives four insert/select/AX read sequences. The same source/build setup without the guards crashes on its first sequence. Debug plugin-load logs verify each control used the intended private library. An initial attempted override loaded the system plugin instead and is excluded from positive qualification.

The patched developer Mumble client then passes Add Server, fingerprint inspection of the owned loopback server, native connected channel/user display, declining initial file identity setup, choosing a generated 46-byte fixture, reopening identity setup on retry, and cancelling again. No identity passphrase was created or entered. Client quit is corroborated by process exit, plugin unloads and the disposable settings' clean-quit marker. The owned test server was stopped. The [37 enabled local CTest suites](local-regression.txt) pass in 40.60 seconds with zero failures/execution skips; the existing OverlayTest remains disabled. These are limited developer-runtime checks, not complete native delivery or media acceptance.

## Shipping build repair

For macOS static Qt **6.10.0** builds, the client now rebuilds Cocoa from pinned upstream source with the patch. The source archive SHA-256, original accessibility file SHA-256 and corrected file SHA-256 are checked. Reconfiguration accepts only the verified original or corrected file. Qt's import/interface metadata is retained, while its imported Cocoa archive points to the new archive in this build. The installed/cached vcpkg archive is never changed. The downloaded Qt source retains its upstream license; existing Qt license distribution continues.

The vendor target follows Qt's own compiler/deployment requirements, compiles without Mumble's application warning flags, and disables unity compilation. Cocoa targets macOS 14 as upstream requires; the product minimum stays macOS 15. Windows/Linux and other Qt versions do not enter this repair path. An explicit `qt-cocoa-accessibility-repair=OFF` option exists for the unpatched comparison build; that build remains unqualified for release while this crash is open.

Hosted static ARM/Intel builds, regression suites and a fresh packaged ARM preview must confirm this build integration. The preview must reproduce the native positive flow without the experimental Homebrew plugin override. Signing/notarization, macOS 15/27 native desktop coverage, identity unlock and complete delivery, microphone/camera capture, six directed platform pairs and the combined frozen candidate remain separate acceptance gates. [Validation identities](validation.json) preserve the private experiment's scope.
